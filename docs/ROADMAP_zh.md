# MoonSpoof 路线图

[English](../ROADMAP.md)

规划更新于 2026-10-18。根据项目负责人反馈，项目已通过初审。本文是后续开发计划，不代表已经通过终审或投入生产使用。

## 目标

将 MoonSpoof 做成可供 MoonBit 项目接入的账号与包名混淆检测库。先完成一个完整的账号注册接入，再完善决定检测结果的 Unicode 机制。浏览器演示用于查看证据；库的正确性与可接入性决定开发进度。

## 当前基线

- 已发布 [v0.1.0](https://github.com/Sidney-sunny/MoonSpoof/releases/tag/v0.1.0)，包含 MoonBit API、JavaScript 引擎产物与双语演示站。
- 已实现 Unicode 16.0.0 NFD、完整默认大小写折叠、应用骨架键、字符诊断、自定义策略和批量碰撞分组。
- 已有验证覆盖 19,965 条官方 NFD 向量、99,825 项断言，以及混淆映射、大小写折叠与键稳定性检查。参见[实现范围与证据](SPECIFICATION_zh.md)。
- 已固定六份 Unicode 来源及其校验值，支持校验后原子下载、直接读取官方规范化测试源，并固定 MoonBit 编译器版本。
- 尚存缺口：仅十一类命名字系，没有完整 Script_Extensions、Identifier_Status、混合数字检测或双向骨架重排；尚未记录真实应用接入。

## 里程碑顺序

以下里程碑均处于计划状态，尚未完成。估算按专注开发工作日计算，不是日历承诺；M1 完成后重新估算。目前没有提供比赛截止时间。版本号是提议，必须通过发布门槛后才能确定。

| 顺序 | 交付内容 | 完成证据 | 工作量估算 |
| --- | --- | --- | --- |
| M1 | 可运行的账号注册接入示例 | 通过公开库 API 执行的验收用例 | 2–4 天 |
| M2 | 字系集合与明确的标识符状态策略 | 固定数据、已审核 API 变更、多语言回归 | 4–7 天 |
| M3 | 混合数字检查与参考实现对照 | 可复现结果及差异解释 | 3–5 天 |
| M4 | 接入复核与拟议 v0.2.0 发布 | 发布门槛通过、迁移说明、产物验证 | 2–3 天 |

## M1：完成一个接入闭环

实现一个导入公开 API 的小型可运行 MoonBit 注册示例。在真实应用采用前，明确称为参考接入，不将仓库示例描述为外部使用。

验收条件：

- [ ] 从全新检出运行一条文档中的命令，即可加载已有名称并检查待注册名称，无须启动演示站。
- [ ] 区分允许注册、完全重复、混淆碰撞和策略不通过，返回冲突的已有名称及有用的诊断证据。
- [ ] 可执行用例覆盖 `paypal` / `p\u0430ypal`、合法多语言名称、默认可忽略字符，以及敏感模式与折叠模式中 `I` / `l` 的已记录差异。语法校验与碰撞策略选择明确由应用决定。
- [ ] 持久化键时记录库版本、数据版本和键策略，演示升级版本或更换策略后重建索引。说明并发生产存储需要原子执行碰撞约束，不声称内存示例已提供这一能力。
- [ ] 中英文接入说明标出导入方式、调用位置、预期决策和限制；测试通过公开 API 验证接入行为。

## M2：完善字系与标识符决策

优先补齐字系分析限制，再考虑增加启发式风险分数。引入更精确的 Unicode 检查时，继续明确记录现有应用行为。

验收条件：

- [ ] 在已审核来源清单中固定 Unicode 16.0.0 Script_Extensions 和 Identifier_Status 数据，包含官方 URL、校验值、离线校验测试和可复现生成。
- [ ] 设计并审核完整字系集合及 Script_Extensions 解析的表达方式；更新生成接口前，记录与现有公开字系分类的兼容关系。
- [ ] 新增显式选择启用的 Identifier_Status 策略，提供可处理的拒绝证据。与应用语法校验及现有默认策略分开，除非明确记录破坏性变更。
- [ ] 为共享/继承字符、CJK 组合、原先归为 Unknown 的字系和受限标识符补充多语言回归。对照固定版本规范复核限制等级估计，记录剩余缺口。
- [ ] 同步更新 API 契约、范围、迁移说明和测试。已有持久化键行为必须保持稳定，或明确要求迁移。

## M3：验证数字混用与参考行为

参考对照使用相同的固定 Unicode 版本。由 MoonSpoof 应用扩展引起的差异必须单独列出，不能变成无法解释的通过或失败。

验收条件：

- [ ] 基于完整且固定的数字属性数据实现混合数字检测，测试单一十进制数字系统、混用系统及检查范围外字符。
- [ ] 增加与 Unicode 数据兼容的固定 ICU 构建之间的可复现对照工具，记录 ICU/数据版本、对照 API、语料和命令；可选参考依赖不进入库运行时。
- [ ] 将标准机制与全角折叠、默认可忽略字符处理、稳定应用键和大小写折叠策略分开，解释已提交对照语料中观察到的每项差异。
- [ ] 扩充组合标记、非 BMP 字符、控制字符和长输入等对抗与多语言回归，保留双字符串/批量等价关系及键稳定性检查。
- [ ] 发布覆盖矩阵，区分已实现机制、已测试行为和延后工作；对照通过不代表完整 UTS #39 合规。

## M4：复核接入并发布

拟议 v0.2.0 必须完成 M1–M3 并满足以下门槛。范围调整时，先更新本计划与发布说明，再确定版本号。

验收条件：

- [ ] 从全新检出运行 M1 接入示例并记录结果。如有外部或负责人自用应用，经许可记录真实调用位置和反馈；否则明确保留“仅参考接入”的采用状态。
- [ ] CI 中 WASM、JavaScript 和 native 测试通过；生成器测试、官方 Unicode 验证、浏览器 ABI/Worker 检查和生产构建通过。运行 `moon info`、`moon fmt` 并审核接口和生成数据变更。
- [ ] 发布键生成与批量分组的可复现测量，注明语料、规模、运行时、工具链和硬件；只有存在同等条件下的受控测量时才进行竞品性能比较。
- [ ] 复核 API/数据兼容性、索引重建、中英文安装说明、更新日志和实现范围。MoonBit 包注册表发布状态与 GitHub 发布产物分别验证，再宣传对应安装路径。
- [ ] 确认提交、标签及推送认证身份均对应 `Sidney-sunny`；全部门槛通过后发布已审核的标签、说明、产物与校验值。

## 接下来两轮实现

1. **注册接入：**完成范围明确的 M1，附公开 API 验收测试与双语说明。这是路线图后的首要编码任务。
2. **字系基础：**启动 M2，先完成已审核来源元数据、可复现数据表和字系集合 API 决策。必要时后续继续完成 M2，不能只生成表就标记里程碑完成。

以上描述未来的实现工作。本次新增路线图与同步产品文档的两轮文档推送不代表 M1 或 M2 已完成。

## 范围控制

- 核心保持为可复用的 MoonBit 库；证明接入不需要新增账号服务器、数据库框架或 UI 平台。
- 此阶段继续固定 Unicode 16.0.0；后续 Unicode 升级单独安排数据与兼容性审核。
- 延后完整双向骨架重排、NFKC/NFKD、IDNA/域名校验、区域相关大小写及完整合规声明；只有明确用途和验收语料后才重新评估。
- 优先修复正确性和接入阻碍；单纯 CI 加固与视觉打磨不构成产品里程碑完成。
- 只有链接到可执行证据后才勾选里程碑；外部采用只在实际发生后记录。
