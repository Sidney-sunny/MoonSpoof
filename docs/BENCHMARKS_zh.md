# MoonSpoof 0.2.0 性能报告

[English](BENCHMARKS.md)

于 2026-10-30 使用准备发布的 0.2.0 候选代码和固定的 0.10.18 编译器测量。[benchmark-results.json](benchmark-results.json) 保存全部计时轮次、环境、语料与输出哈希。本报告替换 2026-10-11 的结果；旧版的语料和编译器不同，不能据此声称前后性能提升。

## 复现

在仓库根目录执行：

```powershell
pnpm --dir playground run engine
node tools/bench.mjs --check-fixtures
node tools/bench.mjs --output docs/benchmark-results.json
```

已有的 `pnpm --dir playground run bench` 会重建 release JavaScript 引擎并打印报告。直接运行 Node 命令会测量现有引擎，并检查本机编译器是否匹配 [.moon-version](../.moon-version)。测量期间停止占用 CPU 的构建与测试。若计时期间引擎产物发生变化，脚本直接报错。主机负载、电源管理、V8 和操作系统调度都会影响结果。

## 方法与结果

[bench.mjs](../tools/bench.mjs) 在同一进程按表格顺序执行八个场景。每个场景先预热，再用 `performance.now()` 顺序执行五轮。键生成预热 1,000 次完整语料遍历，批量预热 20 次完整扫描，报告接口预热 1,000 次调用。JSON 按执行顺序保存五轮耗时及最小/最大值。表格展示中位轮次总耗时，以及该轮次计算出的每单位平均耗时；它不是单个标识符延迟的百分位数。

| 场景 | 每轮迭代 | 每次迭代单位数 | 中位轮次 ms | 每单位平均微秒 | 每秒单位数 |
| --- | --- | --- | --- | --- | --- |
| 直接生成普通键 | 1,000 | 32 | 68.5589 | 2.1425 | 466,752 |
| 直接生成折叠键 | 1,000 | 32 | 122.4928 | 3.8279 | 261,240 |
| 1,000 名普通策略批量 | 20 | 1,000 | 56.7753 | 2.8388 | 352,266 |
| 1,000 名折叠策略批量 | 20 | 1,000 | 93.553 | 4.6776 | 213,783 |
| 10,000 名普通策略批量 | 20 | 10,000 | 702.953 | 3.5148 | 284,514 |
| 10,000 名折叠策略批量 | 20 | 10,000 | 1,148.8396 | 5.7442 | 174,089 |
| 易混淆字符串对 JSON 报告 | 10,000 | 1 | 204.5253 | 20.4525 | 48,894 |
| 西里尔字母 + ZWSP JSON 诊断 | 10,000 | 1 | 414.3281 | 41.4328 | 24,135 |

键生成每次迭代对全部 32 个名称调用 `spoof_skeleton` 或 `spoof_skeleton_case_folded`，即每轮生成 32,000 个键。计时包含 JavaScript 循环与输出长度累加，不构造诊断报告或 JSON。两种键策略分别记录输出 SHA256；每次预热和计时轮次结束后都检查输出累加值。

批量的单位是名称，计时包括换行解析、键生成、哈希分组、JSON 序列化与 `JSON.parse`。普通和折叠策略扫描相同语料。比较及诊断的单位是调用，包含报告构造与 JSON 序列化，仅消费返回字符串，不解析 JSON。字符串对和诊断的精确输入及哈希也保存在 JSON 中。

计时不包含引擎构建、语料构建、正确性预检、网络/磁盘 I/O、线程通信和 DOM 渲染。GC 与操作系统调度包含在内。本报告仅测量该 Node 主机上的 release JavaScript；没有测量 native/Wasm 运行时、浏览器交互、内存分配/峰值内存和注册表/数据库 I/O。

## 语料与正确性预检

[benchmark-fixtures.mjs](../tools/benchmark-fixtures.mjs) 定义完整固定顺序。键语料涵盖 ASCII、大小写变体、希腊/西里尔易混淆字符、不可见字符移除、规范等价、组合符重排、大小写展开、补充平面字符、中日韩、印度文字、泰语、希伯来语和阿拉伯语。32 个名称共 179 个代码点，单个名称长 2–17 个代码点。重复遍历测量固定热语料，不代表随机生产分布或长输入压力测试。

| 名称数 | UTF-8 字节数（含 LF 分隔） | 代码点数（不含分隔符） | 输入 SHA256 |
| --- | --- | --- | --- |
| 32 | 339 | 179 | `58ad4bbbe31d45bd32a744f6c3dcb7dabaf57fe1592da4e851a013029497f8d9` |
| 1,000 | 9,498 | 8,199 | `bb5f4d417cf99a5e1d08933528ee39e1a4f5a17b5f4ae23b534fba3b86c0dd67` |
| 10,000 | 104,898 | 91,899 | `77780123a220686894984fd8103cb95413a56e0cb916123d4d1d71316f95c005` |

哈希对名称以 LF 连接后的 UTF-8 字节计算，不含末尾 LF。批量语料没有完全重复的名称；每十个名称包含四种 PayPal 变体、三种 admin 变体、一个独有 user 名称及一对 Team/team。1,000 名语料的普通策略产生 200 组/400 个冲突名称，折叠策略产生 300 组/900 个；10,000 名对应 2,000 组/4,000 个与 3,000 组/9,000 个。折叠策略返回更多结果，这部分工作包含在计时内。

计时前执行大小写、易混淆和规范等价的已知断言，并通过独立 JavaScript Map 对公开键输出分组，逐组核对批量接口的全部成员。这是批量 ABI 一致性预检，不能替代 Unicode 一致性测试或固定 ICU 差异语料。10,000 名扫描直接调用无限制 ABI，超过演示线程 5,000 名上限。

## 扩展性与解读边界

在本语料中，将批次从 1,000 名增加到 10,000 名，普通策略的中位完整调用由 2.84 增至 35.15 ms，折叠策略由 4.68 增至 57.44 ms。大批次还包含更长的数字后缀及更多、更大的输出分组。这些结果只描述对应输入，不构成固定扩展规律或服务延迟保证。

查表使用二分搜索；NFD 可能展开字符并重排组合片段，键生成可能经过多轮归一化。批量对生成的键哈希分组，不逐对比较。成本取决于输入代码点、键展开、输出规模和运行时行为。本报告不支持固定 O(N) 吞吐量保证、统计置信区间、竞品排名或完整 UTS #39 合规声明。
