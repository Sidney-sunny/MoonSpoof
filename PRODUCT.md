# MoonSpoof product

[Chinese](docs/PRODUCT_zh.md)

## Platform

web

## Users

Hackathon judges evaluating the project's technical contribution, correctness, usability, and integration potential. Confirmed by the project owner.

## Product Purpose

Make visually confusable Unicode identifiers inspectable and demonstrate a reusable MoonBit security library through real, locally executed inputs.

## Positioning

A dependency-free MoonBit engine with generated Unicode 16.0 data, character diagnostics, configurable identifier policies, and skeleton-indexed batch collision grouping. The browser uses the compiled JavaScript target; WASM and native are separate library targets.

## Operating Context

Judges open the showcase, compare two identifiers, inspect character evidence, scan a list, and examine implementation and competitor references.

## Capabilities and Constraints

Preserve the public library API where practical. Unicode security analysis is a signal, not proof of malicious intent. Full UTS #39 compliance must not be claimed without implementation and conformance evidence. Browser execution does not transmit entered text. User authorized architecture and implementation refactoring.

## Brand Commitments

MoonSpoof name and the original crescent-and-twin-loop logo in docs/assets/logo.jpg; English technical artifacts; Chinese conversation; bilingual website; dark, matte, minimal visual presentation. The owner requested a fresh palette to distinguish another project: ink blue and ice cyan. Avoid decorative starter chips and fabricated benchmark claims.

## Evidence on Hand

MoonBit source and tests, Unicode data generator, Apache-2.0 license, existing architecture and API documentation. Official ICU and confusable_homoglyphs APIs support feature comparisons. No controlled competitor performance benchmark is available.

## Product Principles

1. Demonstrate working code before making claims.
2. Show codepoints and rules behind every diagnostic.
3. Describe supported behavior and remaining standard gaps precisely.
4. Keep user input on the device.
